# Руководство контрибьютора

**Язык:** [English](CONTRIBUTING.md) | **Русский**

Благодарим за интерес к участию в разработке Polygram! В этом документе описан процесс внесения вклада в проект.

## Как внести вклад

1. Сделайте форк репозитория на GitHub.
2. Создайте ветку функции из `main`: `git checkout -b feature/your-feature-name`
3. Внесите свои изменения.
4. Запустите тесты: `cargo test`
5. Запустите clippy: `cargo clippy -- -D warnings`
6. Зафиксируйте изменения с описательным сообщением коммита.
7. Отправьте в свой форк: `git push origin feature/your-feature-name`
8. Откройте pull request в ветку `main`.

## Соглашения по документации

Вся документация следует методологии **Docs-as-Code** со структурой **Diátaxis**:

- `docs/` — продуктово-техническая документация (английский + русский)
- `handbook/` — база знаний компании (английский + русский)
- Имена файлов: kebab-case, только английский в нижнем регистре, цифры и дефисы
- Ссылки: только относительные Markdown-ссылки (`[Текст](../path/file.md)`)
- Каждый файл `.md` должен иметь YAML-фронтматер и переключатель языков
- Каждая папка должна содержать файл `README.md`

## Зоны ответственности

- `src/` — полный доступ для агентов (код + документация модулей)
- `extensions/` — полный доступ для агентов (расширения + CONTRACT.md)
- `.agent-workspace/` — полный доступ для агентов (планы, логи, черновики)
- `docs/` — только чтение для агентов (источник истины технической спецификации)
- `handbook/` — только чтение для агентов (стратегия, бизнес, маркетинг компании)

## Кодекс поведения

Будьте уважительны и конструктивны. Следуйте существующему стилю кода и соглашениям.

## Лицензия

Внося вклад, вы соглашаетесь, что ваши вклады будут лицензированы по лицензии проекта.
