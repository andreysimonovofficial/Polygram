# Статус-движок

**Язык:** [English](../en/03-reference/status-engine.md) | **Русский**

## Терминология и состояние вычислений

Терминология: В коде и интерфейсе термин In полностью заменен на Request (Запрос).

Статусы Запроса (Request): Удовлетворён / Ожидание (слово «Дефицит» убрано из UI, чтобы не путать пользователя).

Статусы Результата (Result): Ожидание / Избыток.

Главное правило: Если в Запросе Ожидание, Результат строго блокируется.

## Состояния Показателей

Состояние считается автоматически по связям:

1. Запрос (Статусы):
   1.1. Удовлетворён (Ok, зелёный) = Сумма Результатов Источников ≥ Запрос;
   1.2. Ожидается (Expected, красный) = Сумма Результатов Источников < Запрос;
2. Результат (Статусы):
   2.1. Обеспечен (Ok, зелёный) = Сумма Запросов Целей = Результат;
   2.2. В избытке (Surplus, жёлтый) = Сумма Запросов Целей < Результат;
   2.3. Ожидается (Expected, красный) = Сумма Запросов Целей > Результат и флаг “В процессе” деактивирован;
   2.4. В процессе (InProgress, синий) = Сумма Запросов Целей > Результат и флаг “В процессе” активирован;

Приоритет статусов (Какой показывать, если несколько статусов одновременно. Самый первый = высший приоритет):

1. Ожидается;
2. В процессе;
3. В избытке;
4. Обеспечен / Удовлетворён;

Когда запрос удовлетворён — процесс (блок) выполняет Свою задачу ASAP.

Статус пишется в определённом месте на теле Процесса.

## Числовой пример

Показатель можно добавлять абсолютно в любой вход и запрос любого Процесса. Но значения в каждом Процессе этого Показателя назначаются индивидуально. У Показателя имя, ID, тип, единица измерения везде одинаковые.

Например — в Результате Процесса "Продажа товаров" — Выручка 10 $, она идёт в запросы Процессов "Сотрудник 1" и "Сотрудник 2", один из которых получает 7 $, а второй 2 $, статус в результате "Продажа товаров" = Избыток (Так как израсходовано 9 $), статус у каждого запроса сотрудников = Удовлетворён.
