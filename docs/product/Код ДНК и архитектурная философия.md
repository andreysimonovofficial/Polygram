# "Код ДНК" и архитектурная философия

Сам Polygram в своей основе это чистый CAD с коннекторами API, MCP и.т.д... Система модульная. Можно создавать абсолютно любые расширения. Всё максимально бесшовно подключается. Какие бы расширения Ты не подключал, всё равно это по факту просто передача данных. Запрос и результат. Всё просто. Polygram просто делает это всё визуально эргономичным и производит вычисления (Коэфициэтны, формулы и.т.д...).

* Ядро CAD хранит граф, холст и официальные базовые действия.  
* Расширения объявляют инструменты и их команды.  
* Мышь, клавиатура и MCP используют один механизм команд.  
* Панорамирование, выделение и связи становятся расширениями.  
* Агент создаёт или обновляет расширение, после чего оно появляется на холсте.  
* Ванильное ядро не меняется при добавлении расширений.

### Расширения

**Автоматизированная система диверсификации ответственности и фонового партнёрства.**

Cкачивание репозиториев с GitHub и если они полезные – превращение их в расширения Polygram. То есть – когда то приложение или код Мы в Polygram монетизируем – Мы по лицензии платим разработчикам того репозитория роялти. Таким образом концентрация идёт на ключевой функционал Polygram, а дополнительные функции делегируются партнёрам.

* Принцип: Расширения хранятся в отдельных локальных репозиториях (`/extensions`).  
* Правило ДНК: Какие бы изменения ни вносились в расширения, они никогда не влияют на чистый код ванильного CAD.  
* Универсальность UI: Каждый элемент интерфейса может дополняться расширением через динамическое меню.  
* Агент по MCP может делать extension create / extension update. Тем самым делая те самые модули для CAD. Пользователь ощущает Себя реальным начальником. Полная автономия: Агент создает/обновляет extension и сразу подключает его к холсту без лишних вопросов.

### Терминология и состояние вычислений (Строгая математика)

* Терминология: В коде и интерфейсе термин In полностью заменен на Request (Запрос).  
* Статусы Запроса (Request): Удовлетворён / Ожидание (слово «Дефицит» убрано из UI, чтобы не путать пользователя).  
* Статусы Результата (Result): Ожидание / Избыток.  
* Главное правило: Если в Запросе Ожидание, Результат строго блокируется.

### Базовые расширения ядра (Core Extensions)

* «Секретарь»: Автономный агент коммуникации, который дожимает лиды, назначает встречи и работает бесперебойно через Telegram/почту даже при закрытом браузере, а все сообщения всегда сохраняются в локальную базу.  
* «Финансы»: Прямая интеграция с эквайрингом/банками для вывода реальных показателей финансовых потоков прямо на блоки холста и отображения транзакций.  
* «Контракты» (CONTRACT.md): Долгосрочные задачи с проверками и автоматическими напоминаниями через Секретаря.

### Философия продукта и Дофаминовый цикл (UX/Психология)

* Позиционирование: «Созидай. Управляй. Пожинай». Инструмент обогащения и геймифицированная «addictive» деловая активность, которая пошагово ведет к успеху.  
* Принцип основателя: Продукт делается в первую очередь для себя как идеальное оружие, а пользователям и инвесторам демонстрируется готовый работающий кейс.  
* Прозрачность: Бесплатный свободный доступ к базовому ванильному CAD.

Принцип: Вдумчивый выбор одного максимального рычага и нескольких вторичных на основе глубокого анализа в направлении масштабируемых модулей и в первую очередь реализация максимального рычага в период итерации, откладывая вторичные, а потом переход к следующей итерации.

Лаконичный, элегантный, интересный, простой, удобный, плавный, быстрый, эффективный, гламурный, сексуальный, желанный, свежий (Как чистый прохладный утренний воздух после душной ночи, как приятная горячая питьевая вода после жажды) с принципами, высокоэстетичный, универсальный, Своё дело знает, бесшовный, строгий и надёжный, но доступный, эргономичный и родной.
