# Архитектура: комнаты и двери

Схема: `docs/architecture.mmd` (открывается в любом просмотрщике Mermaid).

## Комнаты (модули)

| Комната | Назначение | Статус |
|---|---|---|
| `core` | Ядро: иерархия, значения и статусы, сетка и линии, команды, события, узкие места | Готово |
| `cli` | Консольный терминал `pg` — запуск ядра без окна, бенчмарки | Готово |
| `canvas` | GPU-холст, камера, уровни детализации, сменная тема | Готово |
| `polygram` | Окно egui: меню, палитра команд, строка статуса, холст | Готово |
| `api` | HTTP и MCP, срезы контекста, права и области | Готово |
| `mcp` | MCP сервер (JSON-RPC 2.0 над stdio) для Claude Desktop и др. | Готово |
| `chat`, `agents`, `storage` | Чаты, агенты и субагенты, файлы `.pg` | Планируются |

Комнату заводим в момент старта её этапа, не раньше.

## Правила дверей (нарушать нельзя)

1. **`core` не знает про окно, графику и сеть.** Проверяется автоматически (`tests/walls.rs`).
2. **Всё меняется только командой** (`Command`). Окно, MCP, API и консоль равноправны.
3. **Всё, что случилось, — событие** с номером ревизии. Из него строятся подписки, чаты, журналы.
4. **Один писатель.** Движок владеет данными в своём потоке; остальные читают неизменяемые снимки.
5. **Файл не длиннее 1000 строк.** Проверяется автоматически. Больше — режем на комнаты.
6. **Производное не хранится.** Статусы, потоки и маршруты линий пересчитываются; в файле — исходное.

## Как устроено ядро

```
Command ──► Engine.exec ──► помечает затронутое ──► finish():
                                                       ├ пересчёт только помеченного (values)
                                                       ├ перекладка линий только затронутых (route)
                                                       └ запись событий с ревизией (event)
```

* **Иерархия** (`hierarchy.rs`) — плоские массивы и числовые индексы; связи — связные списки
  внутри массива (добавление и удаление без выделения памяти).
* **Значения** (`values.rs`) — числовые колонки по показателям; расчёт на один шаг
  «выход → входы», только для помеченных показателей.
* **Архитектура графа** (`layout.rs`, `route.rs`, `autolayout.rs`) — целые клетки сетки,
  запрет наложений через пространственный индекс, ортогональные линии с дорожками.
* **Рантайм** (`runtime.rs`) — движок в своём потоке; клиенты шлют команды и читают снимки.

## Что видит холст

Два снимка: `DynamicState` (числа и статусы, плоские массивы, публикуется при каждой ревизии)
и `Geometry` (карточки и линии, публикуется только при изменении структуры или раскладки).
