# ADR-001: Декомпозиция мега-компонентов и спагетти-кода

## Статус
Принято

## Контекст
В коде приложения Polygram presence большие файлы (>500 строк) со смешанными ответственностями:
- `crates/polygram/src/app/interaction/add_metric.rs` (749 строк) — модальное окно + парсинг значений + календарь + иконки типов
- `crates/canvas/src/lib.rs` (782 строк) — Canvas + Camera + ObjectRect + hit-testing + шрифты
- `crates/canvas/src/paint/object.rs` (624 строк) — рендер процесса + обложка + шапка + контейнеры + пунктир
- `crates/core/src/drag_domain.rs` (587 строк) — доменная логика дропа всех типов объектов в одном файле
- `crates/polygram/src/app/drag.rs` (536 строк) — жизненный цикл драга + free_cell + контейнерный драг
- `crates/polygram/src/app/ui_event.rs` (468 строк) — все события CentralPanel в одном файле
- `crates/polygram/src/app/interaction/cover_modal.rs` (401 строк) — модальное окно + список иконок + сетка + предпросмотр

## Решение
Разбить каждый большой файл на маленькие модули по принципу «один файл — одна ответственность»:

### core/src/drag_domain.rs → модули:
- `free_cell.rs` — поиск свободной клетки, целевой объект, противоположное направление
- `metric_drop.rs` — дроп показателя между объектами
- `object_drop.rs` — точка входа для дропа любого объекта
- `dept_drop.rs` — дроп отдела
- `process_drop.rs` — дроп процесса
- `container_drop.rs` — дроп контейнера (Запрос/Результат)
- `metric_drop_object.rs` — дроп показателя как объекта

### canvas/src/lib.rs → модули:
- `camera.rs` — камера холста (смещение, зум)
- `object_rect.rs` — прямоугольник объекта в координатах сетки
- `hit_test.rs` — определение объекта/шапки/отдела под экранной позицией

### canvas/src/paint/object.rs → модули:
- `cover.rs` — обложка процесса (когда не наведено)
- `process_header.rs` — шапка процесса (иконка, название, #ID, статусы)

### polygram/src/app/drag.rs → модули:
- `free_cell.rs` — поиск свободной клетки внутри отдела
- `container_drag.rs` — драг контейнера/показателя как объекта

### polygram/src/app/ui_event.rs → модули:
- `click_handling.rs` — клики: выделение, добавление показателя, контекстное меню, переименование
- `metric_drag.rs` — перетаскивание показателя: соединение, реордер
- `selection_box.rs` — выделение рамкой

### polygram/src/app/interaction/add_metric.rs → модули:
- `type_icon.rs` — иконка типа, циклический перебор, парсинг значения
- `date_popup.rs` — popup-календарь с выбором времени

### polygram/src/app/interaction/cover_modal.rs → модули:
- `icon_list.rs` — все уникальные иконки Lucide
- `preview_block.rs` — карточка предпросмотра обложки
- `icon_grid.rs` — сетка иконок с поиском

## Последствия
- Плюс: каждая файловая единица имеет одну ответственность, улучшена читаемость и поддерживаемость
- Плюс: жёсткие зависимости между модулями уменьшены через явные интерфейсы
- Минус: увеличено количество файлов, требуется навигация по модулям
- 미누с: временное увеличение количества предупреждений о неиспользуемых импортах
