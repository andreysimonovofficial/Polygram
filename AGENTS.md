# Инструкции для агента

## Помехи

Если пользователь говорит что что-то не работает, то заботливо спроси в чём помеха и лаконично, нетехническим языком помоги пользователю объяснить Его точку зрения, а не навязывай что всё работает правильно.

## Коммиты

После каждого ответа агент обязан сделать атомарный коммит всех изменений, сделанных в ходе этого ответа, но если изменений нет – коммит не делать.

Правила коммита:
- Коммит должен быть атомарным: содержать только изменения, связанные с одним логическим заданием из ответа.
- Перед коммитом проверить `git status` и `git diff`, чтобы исключить лишние/случайные файлы.
- Сообщение коммита писать по agreement репозитория (кратко, по существу, на русском или английском).
- Не коммитить секреты, ключи, бинарные артефакты и файлы из `.gitignore`.
- Не делать `git push` без прямого запроса пользователя.

## Чек-лист перед любой правкой

Перед любым изменением кода определить:

**Она меняет архитектуру (хранилища, команды, ревизии, три хранилища)?** Тогда нужен ADR в `docs/DECISIONS/`, а не просто фикс.

**Декомпозиция бог-объектов и мега-компонентов:** стараться реализовывать «один файл — одна ответственность». Большой файл с разной ответственностью режем на модули.

## Запуск и пересборку polygram

Если редактировали `polygram`, то после ответа обязательно закрывай и пересобирай его:
1. Закрыть `polygram.exe` (например, `Get-Process polygram | Stop-Process -Force`).
2. Собрать и запустить: `Start-Process powershell -ArgumentList "-Command cargo run -p polygram"`.
3. Убедиться, что процесс запущен (не failed) и окно видимо на экране. Если процесс упал — исправить ошибку, собрать и запустить снова.
4. Сделать атомарный коммит изменений (см. правила выше). После коммита кратко сообщить пользователю хеш и сообщение коммита.
5. В самом конце выполнить: `Invoke-RestMethod -Uri "http://192.168.0.10:5000/signal" -Method Post -ContentType "application/json" -Body '{"title": "Agent", "message": "Ready."}'`
   - Всегда вызывать напрямую в PowerShell, не оборачивать в `powershell -Command "..."`.

После каждого ответа приложение должно оставаться запущенным и висеть на экране после отправки сигнала — не закрывать его, оно будет работать до тех пор, пока следущий агент или пользователь сами не закроют его. Ответ не считается завершённым, пока приложение не запущено, не видно пользователю, не сделан коммит и не отправлен сигнал.

## Остановка всех процессов (в конце сеанса или перед пересборкой)

Перед любыми правками и в конце сеанса обязательно остановите все запущенные процессы Polygram, чтобы не оставалось висящих процессов и не было конфликтов на порту 8080:

```powershell
Get-Process polygram, polygram-api, polygram-mcp, claude -ErrorAction SilentlyContinue | Stop-Process -Force
```

## Запуск polygram-api (HTTP API на порту 8080)

`polygram-api` — отдельный процесс, который слушает на `http://127.0.0.1:8080` и нужен для работы MCP-сервера в режиме прокси (`--http http://127.0.0.1:8080`).

```powershell
Start-Process powershell -ArgumentList "-Command cargo run -p polygram-api" -WindowStyle Hidden
```

После запуска подождите 3–5 секунд и проверьте, что порт занят и API отвечает:

```powershell
netstat -ano | Select-String ":8080"
& "C:\Windows\System32\curl.exe" -s --max-time 3 http://127.0.0.1:8080/api/stats
```

Должен вернуться JSON, например `{"edges":0,"metric_defs":1,"object_metrics":0,"objects":8,"rev":1}`.

## Важное про порт 8080

`polygram-api` — один процесс на 8080 (полноценный axum сервер).
`polygram` GUI — тонкий клиент, у него нет встроенного HTTP-сервера и он никогда не биндит порт 8080. GUI только опрашивает `http://127.0.0.1:8080/api/snapshot` через HTTP-клиент.

Если нужно пересобрать `polygram` или `polygram-api` — сначала остановите все процессы, потом собирайте, потом запускайте только нужные.
