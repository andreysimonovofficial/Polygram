# Инструкции для агента

## Помехи

Если пользователь говорит что что-то не работает:
- Заботливо спроси в чём помеха и лаконично, нетехническим языком помоги пользователю объяснить Его точку зрения и составить сценарий UX/UI, а не навязывай что всё работает правильно.
- Выбери часть логики, вынеси её в чистую функцию с понятным входным состоянием и покрой тестами.
- Вноси точечные изменения без побочных эффектов. Потом следущую.
- Утверди сценарий UX/UI.
- Действуем точечными шагами по сценарию. Делаем одну вещь, доводим до идеала, переходим к следущей не ломая прошлую.

## Коммиты

После каждого ответа агент обязан сделать атомарный коммит всех изменений, сделанных в ходе этого ответа, но если изменений нет – коммит не делать.

Правила коммита:
- Коммит должен быть атомарным: содержать только изменения, связанные с одним логическим заданием из ответа.
- Перед коммитом проверить `git status` и `git diff`, чтобы исключить лишние/случайные файлы.
- Сообщение коммита писать по agreement репозитория (кратко, по существу, на русском или английском).
- Не коммитить секреты, ключи, бинарные артефакты и файлы из `.gitignore`.
- Не делать `git push` без прямого запроса пользователя.

## Чек-лист перед любой правкой

Перед любым изменением кода определить:

**Она меняет архитектуру (хранилища, команды, ревизии и.т.д...)?** Тогда нужен ADR в `docs/DECISIONS/`, а не просто фикс.

**Декомпозиция бог-объектов и мега-компонентов:** стараться реализовывать «один файл — одна ответственность». Большой файл с разной ответственностью режем на модули.

## Запуск и пересборку polygram

Если редактировали `polygram`, то после ответа обязательно закрывай и пересобирай его:
1. Закрыть `polygram.exe` (например, `Get-Process polygram | Stop-Process -Force`).
2. Собрать и запустить: `Start-Process powershell -ArgumentList "-Command cargo run -p polygram"`.
3. Убедиться, что процесс запущен (не failed) и окно видимо на экране. Если процесс упал — исправить ошибку не ломая приложение, собрать и запустить снова.
4. Сделать атомарный коммит изменений (см. правила выше). После коммита кратко сообщить пользователю хеш и сообщение коммита.
5. В самом конце выполнить: `Invoke-RestMethod -Uri "http://192.168.0.10:5000/signal" -Method Post -ContentType "application/json" -Body '{"title": "Agent", "message": "Ready."}'`
   - Всегда вызывать напрямую в PowerShell, не оборачивать в `powershell -Command "..."`.

После каждого ответа приложение должно оставаться запущенным и висеть на экране после отправки сигнала — не закрывать его, оно будет работать до тех пор, пока следущий агент или пользователь сами не закроют его. Ответ не считается завершённым, пока приложение не запущено, не видно пользователю, не сделан коммит и не отправлен сигнал.
