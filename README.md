# Polygram

Нативный редактор графов процессов на Rust, egui/wgpu и petgraph.

## Запуск

```powershell
cargo run --release
```

Для сборки Windows-бинарного файла:

```powershell
cargo build --release
```

Готовый исполняемый файл находится в `target/release/polygram.exe`. Для macOS проект собирается Rust toolchain на macOS; упаковка `.dmg` в этой версии не автоматизирована.

## Работа с холстом

- Колесо мыши плавно масштабирует граф относительно указателя; диапазон масштаба — 10–500%.
- Средняя кнопка или правая кнопка мыши панорамирует холст.
- Левая панель инструментов: выделение/перетаскивание, панорамирование, создание связи, меню объектов (процесс, отдел, портал и шаблоны расширений), поиск, масштаб и вписывание графа.
- Контекстное меню правой кнопкой мыши добавляет объект в точке курсора, открывает отдел или выравнивает/вписывает текущий граф.
- В режиме выделения блок следует за указателем без задержки; двойной клик по свободному месту добавляет блок. В режиме панорамирования холст двигается левой кнопкой мыши.
- Для связи выберите инструмент «Связь», нажмите показатель в секции «Выход», затем запрос другого блока. Непокрытый запрос выделяется красным, выбранная линия показывает передаваемое значение; её можно выбрать и удалить через инспектор. Повторные и самосвязи отклоняются.
- В инспекторе добавление запроса или выхода открывает форму с названием, значением, целевым требованием, единицей измерения и необязательным лимитом.
- Для подключенного запроса доступность рассчитывается по значениям выходных показателей. Если один выход связан с несколькими запросами и предложения недостаточно, оно распределяется пропорционально их требованиям; дефицит и избыток отражаются в цвете показателей и связей. Неподключенные показатели сохраняют локальную проверку значения относительно требования.
- «Сгенерировать → 1 000 узлов» создает тестовый граф; «Выровнять граф» размещает его слева направо.
- «Стресс-тест · 1 000 узлов» запускает отдельную локальную симуляцию на графе из 1 000 узлов и 2 000 связей: значения запросов и выходов колеблются, статусы и потоки пересчитываются каждый кадр. Скорость регулируется от 0,1× до 10×, «Остановить тест» ставит симуляцию на паузу. Стресс-тест заменяет текущий граф тестовым; исходный проект можно предварительно сохранить в `.pg`.
- Файлы `.pg` — текстовый формат `polygram/1` с JSON-представлением проекта.

## Быстрая проверка отклика и обратная связь

1. Запустите `target/release/polygram.exe` и нажмите «Стресс-тест · 1 000 узлов». Граф загрузится с анимацией метрик на скорости 10×; скорость можно менять или остановить тест.
2. Откройте «QA / Отзыв». Лимит кадров по умолчанию — 144 FPS, чтобы не ограничивать плавность на высокочастотных дисплеях; VSync по-прежнему ограничит вывод частотой монитора. Сравните перетаскивание/масштабирование во время симуляции и на паузе; при необходимости задайте 30/60/120/144 FPS.
3. Нажмите «Скопировать диагностику» и вставьте отчет в сообщение вместе с описанием `действие → ожидалось → получилось`. Отчет включает граф, FPS, длительность кадра/UI, скорость и длительность пересчета симуляции, размер очереди; ничего не отправляется автоматически.

Отчет показывает окно последних 300 кадров и имя GPU/API. Замер кадров ведется только когда окно в фокусе: Windows может ограничивать FPS фонового окна. `Кадр p95/max` — интервал между кадрами, включая VSync и планирование ОС; `Обработка UI p95/max` — время приложения на подготовку кадра. Если второй показатель мал, а кадры тормозят, задержка находится вне UI-подготовки — в рендерере/GPU/драйвере/композиторе. В приложении включен низколатентный графический swapchain (один кадр в очереди) и раннее пробуждение перед VSync; фоновые точки прорежены. «Вписать граф» или клавиша `Home` возвращает граф в видимую область.

## Метрики и интеграции

Webhook принимает `POST http://localhost:8080/api/v1/tick` с JSON:

```json
{"node_id":"PROC_MKT_01","metric_id":"M_LEADS","value":450.5}
```

Ответ `202 Accepted` означает, что тик добавлен в lock-free очередь; UI применяет накопленные тики при следующем кадре. Переполненная очередь возвращает `429 Too Many Requests`, некорректное значение — `422 Unprocessable Entity`.

REST polling настраивается в инспекторе узла. URL должен возвращать JSON той же формы, что webhook. Частота задается в секундах.

## Локальное хранение метрик

Обработанные приложением тики сохраняются в локальную SQLite-базу: история хранит каждое обновление, а таблица последних значений позволяет восстановить состояние показателей при следующем запуске. HTTP `202` по-прежнему означает только постановку в очередь, не подтверждение записи на диск; при аварийном завершении ещё не записанные обновления могут быть потеряны. Для проектов используется отдельный ID; старые `.pg`-файлы получают его автоматически и сохраняют при следующем сохранении проекта. Сам файл `.pg` по-прежнему содержит граф и настройки, а база не синхронизируется с другими компьютерами.

На Windows база находится в `%LOCALAPPDATA%\\Polygram\\Polygram\\data\\polygram.sqlite3`; в других системах — в пользовательской папке данных приложения. История пока не очищается автоматически и со временем может увеличиваться. Если запись временно невозможна, обновления остаются в ограниченной очереди приложения и ошибка показывается в строке состояния.
